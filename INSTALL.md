# Установка и обучение HUSH на кластере со SLURM

Инструкция рассчитана на Linux-кластер, где есть только SLURM и `module load cuda`.
Всё остальное (conda, компилятор, PyTorch и прочие пакеты) ставится в каталог
пользователя без прав администратора.

## 1. Требования

- **Видеокарты NVIDIA на вычислительных узлах.** Модель и оператор deformable
  attention работают только на CUDA.
- **Модуль CUDA 12.x.** Из него берётся `nvcc` для сборки оператора. Старшая
  версия CUDA модуля должна совпадать с версией, под которую собран PyTorch.
  Окружение по умолчанию рассчитано на CUDA 12, для CUDA 13 см. [раздел 3](#3-окружение).
  Проверка на логин-узле:

  ```bash
  module avail cuda
  module load cuda && nvcc --version
  ```

- **glibc 2.28 или новее** (RHEL/Rocky/Alma 8+, Ubuntu 20.04+). Этого требует
  PyTorch 2.9. Проверка: `ldd --version`.
- **Интернет на логин-узле** для установки пакетов и загрузки весов.
- **Место на диске:** около 10 ГБ под conda и окружение, около 2,6 ГБ под
  чекпоинт обучения.

## 2. Установка conda

Если conda ещё нет, поставьте Miniforge в домашний каталог:

```bash
wget https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
bash Miniforge3-Linux-x86_64.sh -b -p $HOME/miniforge3
source $HOME/miniforge3/etc/profile.d/conda.sh
```

Последнюю команду нужно выполнять в каждой новой сессии. Чтобы это
происходило автоматически, выполните один раз `conda init bash`.

Если домашний каталог маленький, ставьте в другое место, например
`-p /scratch/$USER/miniforge3`. Тогда при отправке задачи укажите
`CONDA_DIR=/scratch/$USER/miniforge3`.

## 3. Окружение

```bash
git clone https://github.com/vision3d-lab/HUSH.git
cd HUSH
conda env create -f environment.yml
conda activate hush
```

Окружение `hush` из [environment.yml](environment.yml) содержит:

| Пакет | Версия | Зачем |
| --- | --- | --- |
| python | 3.11 | |
| torch, torchvision | 2.9.1, 0.24.1 (CUDA 12.6) | обучение, загрузчик Structured3D |
| timm | 0.6.12 | слои Swin-энкодера |
| torch-harmonics | 0.6.5 | базис сферических гармоник |
| einops | 0.8.1 | перестановки тензоров |
| numpy | 2.2 | |
| opencv-python-headless | 4.11 | чтение панорам |
| tqdm | 4.67 | прогресс обучения |
| gcc, g++ | 11 | компилятор для сборки оператора вместе с `nvcc` из модуля |
| ninja, setuptools | | сборка оператора |

**Если модуль CUDA не 12.x или видеокарты Blackwell.** Сборка PyTorch задаётся
суффиксом `cu126` в трёх строках `environment.yml`. Замените его до создания
окружения:

| Модуль CUDA | Видеокарты | Суффикс |
| --- | --- | --- |
| 12.x | V100, T4, A100, A40, L40, H100 | `cu126` (по умолчанию) |
| 12.8 или 12.9 | дополнительно B200, RTX 50xx | `cu128` |
| 13.x | T4 и новее | `cu130` |

```bash
sed -i 's/cu126/cu130/g' environment.yml
```

Если окружение уже создано, удалите его командой `conda env remove -n hush` и
создайте заново.

## 4. Веса Swin-L

При создании модели загружаются веса Swin-L ImageNet-22k (около 800 МБ).
Вычислительные узлы часто не имеют доступа в интернет, поэтому скачайте веса
заранее на логин-узле:

```bash
mkdir -p ~/.cache/torch/hub/checkpoints
wget -P ~/.cache/torch/hub/checkpoints \
    https://github.com/SwinTransformer/storage/releases/download/v1.0.0/swin_large_patch4_window7_224_22k.pth
```

Если домашний каталог маленький, задайте `export TORCH_HOME=/scratch/$USER/torch`
и положите файл в `$TORCH_HOME/hub/checkpoints`. Переменная должна быть задана и
при отправке задачи: `sbatch` по умолчанию передаёт окружение в задачу.

## 5. Сборка оператора Deformable Attention

**Этот шаг можно пропустить.** [train_sf2d3d.sbatch](train_sf2d3d.sbatch) сам
соберёт оператор на вычислительном узле при первом запуске под видеокарту этого
узла и проверит, что оператор на ней работает.

Собрать заранее можно на вычислительном узле в интерактивной сессии:

```bash
srun --gres=gpu:1 --pty bash
module load cuda
source $HOME/miniforge3/etc/profile.d/conda.sh
conda activate hush
bash models/ops/make.sh
cd models/ops && python test.py && cd ../..   # во всех строках должно стоять True
```

Или на логин-узле без видеокарты, явно указав архитектуры:

```bash
module load cuda
conda activate hush
FORCE_CUDA=1 TORCH_CUDA_ARCH_LIST="8.0;9.0" bash models/ops/make.sh
```

**Если на кластере видеокарты разных типов**, а задача может попасть на любой
из них, оператор нужно собрать под все их архитектуры. Укажите их в
`TORCH_CUDA_ARCH_LIST` при сборке вручную или при первой отправке задачи:

| Видеокарта | Архитектура |
| --- | --- |
| V100 | 7.0 |
| T4, RTX 20xx | 7.5 |
| A100 | 8.0 |
| A40, A6000, RTX 30xx | 8.6 |
| L4, L40, RTX 40xx | 8.9 |
| H100, H200 | 9.0 |
| B200 | 10.0 |
| RTX 50xx | 12.0 |

CUDA 13 не поддерживает архитектуру 7.0.

## 6. Запуск обучения

В начале [train_sf2d3d.sbatch](train_sf2d3d.sbatch) поправьте строки `#SBATCH`
под ваш кластер: раскомментируйте `--partition` и `--account`, задайте `--time`
и `--mem`. Остальное задаётся переменными окружения при отправке:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATA_ROOT` | `/path/to/SF2D3D/` | Корень датасета Stanford2D3D, задать обязательно |
| `CUDA_MODULE` | `cuda` | Модуль CUDA, например `cuda/12.4` |
| `CONDA_DIR` | `$HOME/miniforge3` | Каталог установки Miniforge |
| `CONDA_ENV` | `hush` | Имя или путь conda-окружения |
| `CKPT_DIR` | `./checkpoints/sf2d3d` | Каталог для чекпоинтов |
| `EPOCHS` | `100` | Число эпох |
| `BATCH_SIZE` | `2` | Размер батча |
| `TRAIN_LIST`, `VAL_LIST` | списки Stanford2D3D из `filenames/` | Списки файлов для обучения и валидации |
| `EXTRA_ARGS` | пусто | Дополнительные аргументы `train_sf2d3d.py` |
| `TORCH_CUDA_ARCH_LIST` | видеокарта узла | Архитектуры для сборки оператора, см. раздел 5 |
| `MAX_RESTARTS` | `30` | Предел автоматических перезапусков |

Запуск из корня репозитория:

```bash
cd HUSH
DATA_ROOT=/scratch/$USER/SF2D3D/ sbatch train_sf2d3d.sbatch
```

Пути в списках `filenames/` отсчитываются от `DATA_ROOT`, например
`$DATA_ROOT/area_1/pano/rgb/...`.

Состояние задачи и лог:

```bash
squeue -u $USER
tail -f hush-sf2d3d-<номер задачи>.out
```

После перезапусков лог дописывается в тот же файл.

Для Matterport3D и Structured3D поменяйте импорт `Dataset` в начале
`train_sf2d3d.py` и задайте `DATA_ROOT`, `TRAIN_LIST` и `VAL_LIST`.

## 7. Чекпоинты и продолжение обучения

После каждой эпохи в `$CKPT_DIR` сохраняется:

- **`last.pth`.** Полное состояние обучения: веса, оптимизатор, расписание
  learning rate, номер эпохи, лучший RMSE, история метрик и состояния
  генераторов случайных чисел. Весит около 2,6 ГБ. Файл записывается
  атомарно, поэтому прерывание во время записи не портит предыдущий чекпоинт.
- **`best_model_SF2D3D.pth`.** Только веса модели с лучшим RMSE на валидации.
  Весит около 0,9 ГБ.
- **`epoch_XXX.pth`.** Копия чекпоинта каждой эпохи. Сохраняется только с
  `EXTRA_ARGS="--keep_all"`. За 100 эпох это около 260 ГБ.

Как работает продолжение:

- **Новый запуск продолжает с последней завершённой эпохи.** По умолчанию
  `train_sf2d3d.py` подхватывает `$CKPT_DIR/last.pth`, если он есть. После
  отмены задачи, сбоя узла или падения достаточно снова выполнить `sbatch` с
  тем же `CKPT_DIR`.
- **Перед лимитом времени задача перезапускается сама.** За 10 минут до конца
  SLURM присылает сигнал, скрипт останавливает обучение и ставит задачу
  обратно в очередь через `scontrol requeue`. Незаконченная эпоха после
  перезапуска считается заново.
- **Если перезапуск запрещён на кластере**, в логе будет предупреждение. Тогда
  отправьте задачу снова или заранее поставьте цепочку:
  `sbatch --dependency=afterany:<номер задачи> train_sf2d3d.sbatch`.
- **Одна эпоха должна помещаться в лимит `--time`**, иначе задача будет
  перезапускаться, не продвигаясь. На Stanford2D3D при батче 2 эпоха содержит
  520 итераций.
- **Начать с нуля** проще всего с новым `CKPT_DIR`. Продолжить из конкретного
  файла: `EXTRA_ARGS="--resume /path/to/epoch_010.pth"`.
- **Число эпох можно увеличить при продолжении**, например `EPOCHS=150`.

## 8. Частые ошибки

| Сообщение в логе | Причина и решение |
| --- | --- |
| `module: command not found` | В batch-режиме не инициализированы модули. Скрипт пробует подключить `/etc/profile.d/modules.sh` и `lmod.sh`. Если их нет, узнайте путь к скрипту инициализации у администраторов. |
| `conda not found` | Miniforge установлен не в `$HOME/miniforge3`. Задайте `CONDA_DIR`. |
| `nvcc is CUDA 13.x, but torch is built with CUDA 12.6` | Версия модуля CUDA не совпадает с PyTorch. Загрузите модуль 12.x через `CUDA_MODULE` или пересоздайте окружение с `cu130`, см. раздел 3. |
| `GLIBC_2.28 not found` при `import torch` | Слишком старая ОС узла. PyTorch 2.9 требует glibc 2.28. |
| `the op does not run on this GPU` | Оператор собран без архитектуры этой видеокарты. Выполните `pip uninstall -y MultiScaleDeformableAttention` в окружении и отправьте задачу с нужным `TORCH_CUDA_ARCH_LIST`, см. раздел 5. |
| `ModuleNotFoundError: No module named 'MultiScaleDeformableAttention'` при ручном запуске | Оператор не собран или собран в другом окружении. См. раздел 5. |
| `download failed` для весов Swin-L | У вычислительного узла нет интернета. Скачайте веса на логин-узле, см. раздел 4. |
| `$'\r': command not found` | Скрипт скопирован с Windows с окончаниями строк CRLF. Выполните `sed -i 's/\r$//' train_sf2d3d.sbatch models/ops/make.sh` или клонируйте репозиторий на кластере. |
